# Kesonode 插件 · 安装说明书

本文件所在的 `插件版本/` 文件夹，是**所有插件安装包的唯一存放位置**：就在源码文件夹
的根目录里，打开项目一眼就能看到，不用再去 `dist/`、`web-ext-artifacts/` 里翻。

## 新版本怎么放（约定）

每出一个新版本，就在 `插件版本/` 下建一个 `v版本号/` 子文件夹，把该版本的安装包
和一份本说明书一起放进去：

```
插件版本/
├── 安装说明.md                      ← 本文件（通用版，复制到新版本目录里）
├── v1.5.1/
│   ├── kesonode-chrome-1.5.1.zip       Chromium 用
│   ├── kesonode-firefox-1.5.1.zip      Firefox 用
│   └── 安装说明.md                    每个版本都带一份
└── v1.5.2/ ...
```

- 本地安装包由 `npm run package:source` 生成在 `web-ext-artifacts/source/`，复制到对应
  版本目录即可。`插件版本/**/*.zip` 是 `.gitignore` 的**例外、会进仓库**（各版本镜像）；
  其余位置的 zip 仍被忽略，不会误提交。
- `store` 变体是上传应用商店用的，文件名和 source 版几乎一样、只差几十字节，
  **不要和本地安装包混放**，否则容易拿错。

## 安装前

- 支持 Chrome / Edge / Brave 等 Chromium 浏览器，以及 Firefox 和 Firefox 系浏览器。
- **zip 要先解压**：浏览器加载的是「文件夹」而不是压缩包。解压后打开文件夹，
  应该能直接看到 `manifest.json`，记住这一层的路径。
- 解压后的文件夹不要删、不要移动，浏览器运行期间会一直从这里读取插件。

## Chromium（Chrome / Edge / Brave）

1. 地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`，Brave 用
   `brave://extensions`）。
2. 打开右上角的「开发者模式」。
3. 点「加载已解压的扩展程序」，选中**直接含 `manifest.json`** 的那一层文件夹。
4. 装好后建议把 Kesonode 固定到工具栏，方便随时打开。

## Firefox

1. 地址栏输入 `about:debugging#/runtime/this-firefox`。
2. 点「临时载入附加组件」，选择解压文件夹里的 `manifest.json`。
3. 注意：**临时加载在浏览器重启后会失效**，需要重新载入一次。Kesonode 目前没有
   上架任何扩展商店，也就没有签名版；每次重启浏览器后重新载入一次即可。

## 装好之后（第一次使用）

安装完成后会自动打开设置向导：选存储位置（Google Drive / GitHub / WebDAV）
→ 登录或填写凭据 → 勾选要同步的内容（书签默认开）→ 选择是否开启端到端加密
→ 完成首次同步。之后点工具栏图标看同步状态，在选项页改设置。

多台设备要连**同一个后端、同一个账号**；开了加密就必须用**同一个口令**。口令丢失后
加密数据无法恢复，请存进密码管理器。

## 几个要紧的提醒

- 这里的安装包是不含 Kesonode 自带 Google OAuth 密钥的 `source` 构建：
  **GitHub、WebDAV 开箱即用**；要用 Google Drive，需自己创建 OAuth 客户端
  （`drive.file` 权限），并把 `https://<扩展ID>.chromiumapp.org/gdrive` 加入授权
  重定向 URI。扩展 ID 在 `chrome://extensions` 的插件卡片上可以看到。
- 本地加载的扩展 ID 与商店版不同，商店版已保存的账号授权不会带过来；同步数据本身
  存在你自己的网盘 / GitHub 里，连上同一个后端即可读到。
- **升级到新版本（一次性迁移，只需做一次）**：
  1. 如果现在装的是 1.5.1，先把 1.5.2 的文件**覆盖到你当前正在加载的那个文件夹**
     （不要新建目录、不要先移除旧版），在扩展页点插件卡片上的 ↻ 刷新。此时扩展 ID
     没变，原有设置都还在。
  2. 打开选项页 → 高级 → 导入/导出 → 点「导出配置」，会下载
     `kesonode-settings-日期.json`。**默认导出的文件不含任何登录凭据**：后端地址、
     文件夹、同步项等设置都在，但 WebDAV 密码、GitHub Token、加密口令和 Drive 授权
     不在里面，换机后按提示重新登录即可。如果希望一次带走，勾选「包含登录凭据」并
     设一个密码，整份文件会先在本地加密（AES-256-GCM）再下载；**这个密码不会保存，
     丢了就打不开文件，请妥善保管、不要上传到公开位置。**
  3. 从 1.5.3 起，安装包已固定扩展 ID：把新版解压到**全新的** `v版本号/` 文件夹，
     移除旧版后用新文件夹「加载已解压」→ 选项页同一位置点「导入配置」，选刚导出的
     JSON。导入时会问一次「这份配置来自另一台设备或另一个浏览器吗」：选
     **「作为新设备导入」（推荐）** 会重新生成设备 ID 和默认设备名，避免两台浏览器
     写同一份同步文件；只有同一台设备升级/重装时才选「取消 / 恢复本机身份」。
     1.5.17 及更早版本导出的文件会带上后端账号、加密口令与 Drive 授权；1.5.18 起
     默认不带，导入后按提示重新登录（加密口令则按导入面板的提示补填）。
  4. 以后每次升级：直接解压新版、加载即可，配置自动保留，不用再导出导入，也不用
     记住「必须覆盖同一个文件夹」。
- **过渡期（还在用 1.5.2 及更早的包）**：换成新文件夹 = 换扩展 ID = 设置不保留。
  请始终覆盖同一个文件夹并点 ↻，或先导出配置、加载后再导入。
- **从 1.5.3 起不要把新版解压覆盖到旧文件夹**，务必用全新目录。构建产物里
  `chunks/` 的文件名带内容哈希，覆盖解压只会新增新文件、不会删除旧文件，于是新
  HTML 和旧 chunk 混在一个目录里，可能出现 `Unexpected token 'export'`、弹窗或
  设置页空白。固定扩展 ID 后换文件夹不会丢设置，没有覆盖的必要。
- 配置备份也可用于换电脑、换浏览器、重装浏览器、Firefox 临时加载失效等场景，
  不必重新填写后端账号与加密口令。
- 固定扩展 ID 后，自建 Google OAuth 客户端只需注册一次重定向 URI
  `https://<扩展ID>.chromiumapp.org/gdrive`，换版本文件夹不会再变。
- 卸载：先在扩展页移除插件，再删除解压出来的文件夹。

## 出问题了

| 现象 | 处理 |
|------|------|
| 提示清单文件无效 / 加载失败 | 选错层级了，要选直接含 `manifest.json` 的那一层 |
| 找不到图标 | 在浏览器工具栏的扩展（拼图）按钮里把 Kesonode 固定 |
| 加载后没反应 | 在扩展页点卡片上的 ↻ 重新加载 |
| 新按钮显示 `opt_xxx` 裸 key / 英文，其余界面是中文 | 语言文件在扩展加载时缓存：替换源码后没重启扩展。在扩展页把 Kesonode **关闭再打开**（或点 ↻），再刷新已打开的设置页 / 弹窗 |
| 扩展页报错 `Unexpected token 'export'`、贴出一大段 lucide 压缩代码 | 新旧构建混在同一个目录了。删掉整个旧文件夹，把新版解压到**全新目录**重新加载；不要覆盖解压 |
| Firefox 重启后插件消失 | 临时加载的正常行为，重新载入一次 |
| 同步不动、登录失败、冲突提示 | 见源码根目录 [TROUBLESHOOTING.md](../TROUBLESHOOTING.md)；完整上手见 [GETTING_STARTED.md](../GETTING_STARTED.md) |

## 最后一步：替换源码 / 重装后，关闭再打开扩展

浏览器在**加载扩展的那一刻**缓存 `_locales/` 语言文件，而设置页 / 弹窗的 JS 每次打开
都从磁盘重读。于是「替换了源码但没重启扩展」会出现一种很容易误判的状态：新功能、
新按钮已经在了（JS 是新的），但按钮文字却是 `opt_receipt_clear` 这样的裸 key 或英文
（语言文件还是旧的）。这不是翻译缺失，也不是包坏了。

所以无论是重新安装、还是直接替换已加载文件夹里的源码，最后都请：

1. 在扩展页把 Kesonode 的开关**关闭再打开**（或点卡片上的 ↻ 重新加载）；
2. **刷新已经打开的设置页 / 弹窗**——旧页面不会自动更新；
3. 若仍异常，删掉旧文件夹、把新版解压到**全新目录**重新加载（见上文）。

设置页顶部若出现红色「语言资源未刷新」提示，说明正处于这个状态，按上面三步做即可消失。
